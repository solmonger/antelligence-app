# Night run (2026-10-31): routing by kind, field-notebook ants, more fresh sets

Status: **frozen before any real call** (`docs/research/night-20261031/prereg.json`). Code: `scripts/night_run.py`,
`antelligence/experiments/route.py`, `antelligence/experiments/notebook_exam.py`. Tests:
`tests/smarter_swarm/test_night.py`. Mac prompt: `docs/research/night-20261031/CLAUDE_CODE_PROMPT.md`.

## Why

The first fresh-question run (`docs/research/fresh-20261031/RESULTS.md`) settled one thing and opened two:

- Jev's 18-point lead on AGIEval was likely memory. On new questions it ties the local reader.
- No single setup wins everywhere. The reader is best on word problems (100%) and assignment puzzles (60%). Jev alone
  got every syllogism right (100%) and the ants with notes got 80% of them, against the reader's 62%. So: does
  sending each kind of question to its best setup beat the reader?
- The reader's notes lift the ants by about 10 points. But a wrong reader can pull the ants with it. The field
  notebook (draft PR 24, scripted rumour world, +8 to +10 points) counts each source once. Does reading teammates'
  independent work that way stop the ants copying the reader's mistakes?

Eshaan's Mac is free for about ten hours, so one unattended run tries all of it and writes one report.

## Order

1. **Routing, free.** On set 1 (the first fresh run's saved answers, copied in), for each kind pick the arm with the
   best share right; ties go to the cheaper arm (`route.PREFER`: reader first, Jev last). Reported three ways:
   in-sample (optimistic); split-half (routes picked on a random half of each kind and scored on the other half,
   averaged over 200 splits; leave-one-out is not used because, with near-tied arms, dropping one question flips the
   pick against that very question); and held out. The routes are written to `routes.json` **before any new question exists**. Also, for reference only,
   split-half on the 240 AGIEval questions, where Jev's arms are flattered by memory.
2. **Set 2.** A new fresh set (new seed, 160 questions): reader + 8 ants, Jev, d1-3B. It runs with the first set's
   frozen code and caps, unchanged (each set folder gets a copy of `fresh-20261031/prereg.json`, so the frozen check
   still guards it). Then `route-check` scores the frozen routes on it. **This is the real test of routing.**
3. **Notebook ants**, on set 1 then set 2 (`notebook_exam.py`). It is a second round on top of the saved first round.
   Each ant answers again with a field notebook: every *other* model once, with both of its first-round tries working
   alone (answer and a reason of at most 30 words), then the ant's own two tries. The reader's own answer is never
   shown. Two arms: `nb` (question + notebook) and `nb_notes` (question + reader's notes + notebook). 2,560 local calls
   per set.
4. **Set 3, if time is left**: the same as set 2, plus the notebook if that fits too. It's for tighter ranges when
   pooled.
5. **Pool and report.** Every comparison pooled over all sets (ids prefixed by set), `REPORT.md` and a short block.

**Notebook** (pooled over every set that ran it):

| Question | Yes if | No if |
|---|---|---|
| Does the notebook help? | `nb_notes` vote minus `both` vote at least +3 points, range above 0 | range below 0: "it hurts" |
| Do ants stop copying a wrong reader? | Among questions the reader gets wrong, the share of ant answers that pick the reader's letter drops by at least 5 points from `both` to `nb_notes`, range above 0 | range below 0: "they copy more" |
| Does it beat the reader? | the best notebook arm's range against the reader alone is above 0 | otherwise |

Anything between the two columns reads "no clear change". Under 90% usable notebook answers is "invalid".

## Safety and cost

- Local models only, one in memory at a time. The MLX stand-in starts `mlx_lm.server` on **port 8091**, so the chat
  shim on 8090 is never touched. Ports 11434, 8091 and 8520 must be free at the start, or the run stops.
- A memory watch every minute logs the pressure level, swap, free memory and `fseventsd` size to
  `logs/memory.jsonl`. When pressure is critical, or swap grows by more than 2 GB, it stops the current step and
  every server the script started. It then waits for three normal readings in a row, for up to an hour, and retries
  the step once (caches keep what's done). A second stop on that step skips it. The script only stops processes it
  started itself.
- Jev: each set's frozen cap is 1 cent, and the night's cap is 5 cents. A Jev step that could pass that is skipped.
- Every stage writes its files when it ends, and `state.json` records each stage. A rerun of the same command skips
  finished stages and resumes from the caches. Nothing is committed or pushed from the Mac.

## Time

The first fresh run took 121 minutes for the swarm. The plan budgets about 130 minutes per swarm, 90 per notebook
round, 5 for Jev and 20 for d1-3B. That's about 7.5 hours for steps 1 to 3, so set 3 usually fits without its
notebook.

## Limits

- The router is told each question's kind. On fresh sets that's given by construction; a real system would have to
  tell kinds apart, and this doesn't test that.
- Four kinds and one set to pick on: a route can still be picked by luck. That's why the verdict comes only from the
  held-out set.
- A notebook round costs a second round of calls (16 per question instead of 8). A gain has to be weighed against
  that.
- Code-made questions are more regular than human exam questions (see the fresh-question plan's limits).
