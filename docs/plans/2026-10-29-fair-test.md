# The fair test: does a think-alone swarm beat the best single model? (preregistered)

Date: 2026-10-29. Status: **written and frozen before any model call; amended once (below) after a first attempt
that produced no usable reply, before any result was scored.** Nothing has been measured against a real model yet.
The pass lines, question files, answer files and harness code are fingerprinted in
`docs/research/fair-test-20261029/prereg.json`; `scripts/fair_test.py` refuses to run or score if any of them has
changed since. Changing the test after a run starts makes it a new test, to be re-frozen, rerun from scratch and
reported as such, next to the first one.

## Amendment 1 (2026-10-29, before any usable result)

The first live attempt on Eshaan's Mac returned **no usable reply from any of its 6,820 calls**: every call was
refused by the harness's provider layer with a non-outage error, so every answer was empty and the score was 0
against 0 on exams and 0.25 against 0.25 Brier on forecasts. That is a broken run, not a result, and nothing from it
counts. The run also reported $0 spent: the harness only counted the cost of replies it accepted, so if the portal did
answer, those calls may have been billed without being counted.

Most likely cause, from the code (the run kept only each error's class name, so the reply itself was not kept): the
provider layer compared the model name the portal reports with the requested `deepseek/deepseek-v4.1-flash` letter
for letter, and a portal that spells it differently (say `DeepSeek-V4.1-Flash`) fails that check on every call,
after the call has been billed. The other candidates were ruled out by how the run behaved: a missing key stops the
run before any call, and a bad key, a rate limit or a server error stops it after retries instead of finishing.
A request the portal rejects (HTTP 400 to 404) or a reply cut off at the token cap would also fail every call, and
the next run's smoke check shows which it was.

What changed, harness only. The questions, answers, arms, prompts and pass lines are unchanged:

- The model name check accepts the portal's spelling of the same model (lower case, with or without the vendor prefix,
  with a version suffix) and still refuses any other model. It and the finish check now run after the cost is
  counted, so every billed reply is counted, and the portal's own reported cost is used when it gives one.
- Every failed call is kept with its reason (scrubbed of the key) and is **asked again** on a rerun, never reused.
  The broken run's cache therefore contributes nothing.
- **The run stops after 5 unusable replies in a row** and prints why.
- `smoke` runs one question through every arm (20 calls, well under a cent) and prints the model name the portal
  reports, how the replies ended, the first reply and any problem. Run it before the full run.
- **A run in which under 90% of answers are usable gets no verdict** ("invalid run"), only the reason.

Re-frozen in `prereg.json` after this change. The rule above about refused replies now reads: a reply the harness
refuses (another model, cut off, not in the asked format) is an unusable answer; a failed call is asked again on a
rerun.

## The question

Every win for "think alone, then compare" so far is against a weaker swarm (ants that relay, or that trust the
tick-box), in worlds we scripted or ported, or on answers saved months ago. None shows a swarm of model calls beating
the plain alternative: one good model asked the same number of times. That is the comparison that decides whether
the swarm is worth building, so it is the one we test, on tasks we did not design.

## Who competes

One model fits the budget: **DeepSeek V4.1 Flash** on the Nous portal (`deepseek/deepseek-v4.1-flash`, thinking
off, temperature 0.7, at most 500 output tokens). So the "best single model" is that model at its strongest cheap
setting: ask it the plain question several times and take the majority (exams) or the average (forecasts). This is
self-consistency, a known strong baseline, and it gets exactly as many calls as the swarm.

Per question:

| Arm | Calls | What it is |
|---|---|---|
| `single5` (**baseline**) | 5 | the plain prompt, 5 samples, majority vote or mean probability |
| `swarm5` (**the swarm**) | 5 | 5 ants, the same model, each told to look at the question a different way, each answering **alone**; same combine rule |
| `single10` | 10 | 10 plain samples (the baseline for the 10-call arm) |
| `seen10` | 5 + 5 | the 5 swarm ants asked once more after reading the other four ants' first answers and reasons |

The five ways of looking (`LENSES` in `antelligence/experiments/fair_test.py`):

- Exams: work it out directly; rule out wrong options first; name the rule the question turns on; check each option
  against the facts; find the most tempting wrong option.
- Forecasts: start from the base rate; focus on the specific situation; assume things stay as they are; imagine it
  resolved YES; imagine it resolved NO.

No checker, no judge, no ant sees another in `swarm5`. Replies are one JSON object with a short reason and an answer.

## The tasks (all chosen before any call)

1. **Exams: 240 AGIEval questions** (English multiple choice), 60 from each of four fields: LSAT analytical
   reasoning, LSAT logical reasoning, LogiQA (civil-service logic) and AQuA-RAT (maths word problems). Sampled with
   seed 20261029 by `scripts/fair_test_prep.py`; sources and hashes in `exam_manifest.json`.
   *Caveat:* AGIEval has been public since 2023, so the model may have seen some of it. That raises both arms equally,
   so the comparison stays fair, but the absolute scores may be flattering.
2. **Forecasts: 101 real yes/no questions that resolved between 3 July and 28 October 2026** (48 yes, 53 no), from
   public prediction markets (98 Manifold, 3 Polymarket), across politics 18, economics 15, science and technology
   15, sports 13, weather and climate 11, geopolitics 11, health 9 and business 9. Questions that were near certain
   before they resolved, or whose event had already happened, were left out. Each comes with the market's own crowd
   probability from about a week before it closed.
   *Caveat:* the model's training cutoff is not published. It was released on 10 September 2026, so the 54 questions
   that resolved after that date (26 yes) cannot be in its training data; they get their own secondary line.
   A few markets had loose wording; the gathering notes flag q008, q017, q035, q064, q074, q076, q083, q084 and q090.
   They stay in: dropping questions after seeing results is exactly what this test forbids.

**Answers stay out of every prompt.** Questions and answers live in separate files. `load_questions` refuses any
question row carrying an answer, label, outcome, solution, date of resolution, crowd price or source link. `run`
never opens an answer file; only `score` does, after every call is done.

## Pass lines (primary, fixed now)

Scored per question, compared pair by pair (same question, `swarm5` minus `single5`), 95% interval from 10,000
paired bootstrap resamples (seed 20261029):

- **Exams:** the swarm passes if its accuracy is at least **1 point higher** than the baseline's AND the interval's
  lower end is **above 0**.
- **Forecasts:** the swarm passes if its Brier score (squared error of the probability; lower is better) is at least
  **0.005 lower** than the baseline's AND the interval's lower end of the improvement is **above 0**.

**Verdict:** *supported* if both pass; *mixed* if one does; *not supported* if neither does.

Rules: every question counts. An unusable reply is no vote; an exam question with no usable vote is wrong; a forecast
with no usable probability is 0.5. Probabilities are clipped to 0.01 to 0.99 before averaging. No question is
rerun because its answer looked wrong. A reply the harness refuses (another model, cut off, not in the asked format)
is an unusable answer; a call that failed is asked again on a rerun, never reused (Amendment 1). The run stops after
5 unusable replies in a row, and a run with under 90% usable answers gets no verdict. An outage (rate limit, server error, dropped connection) is retried with backoff and, if it persists, stops the run
without caching anything, so a rerun asks again.

## Secondary results (reported, no verdict)

- `seen10` against `single10`: does a 10-call swarm that reads each other beat 10 plain samples?
- `seen10` against `swarm5`: does reading the others' answers help or hurt, on fresh tasks? (Earlier saved runs say
  it hurts; this re-tests it.)
- Each field on its own, and each way of looking on its own (one ant's score).
- Forecasts only: the crowd's Brier score against the swarm's, and the 54 forecasts that resolved after the model's
  release on their own.

## What each outcome would mean

- **Supported:** a swarm of cheap calls that think alone beats the same model asked the same number of times, on
  outside tasks. Build model ants next (section 0.5 and What next in `2026-10-29-swarm-at-scale.md`).
- **Mixed:** it helps on one kind of task. Find out which feature of that task makes the difference before building.
- **Not supported:** different viewpoints add nothing over plain resampling for this model. Say so plainly. The
  scripted results still stand for what they measured (honest "done", no echo), but the case for a model swarm on
  accuracy would be weak, and the next question becomes whether different *models* (not prompts) help.

A null result means "no gain big enough to see with 240 and 101 questions", not "no gain at all". With 240 exam
questions, a 1-point gain will usually not clear the interval; that is deliberate: a gain too small to see here is
too small to be worth the build.

## Cost

20 calls per question, 6,820 calls in all. Expected about **$0.80** (exams $0.57, forecasts $0.22, at $0.106 / $0.513
per million tokens in / out); about $2 even if every reply ran to the 500-token cap. The run stops itself at
**$3** (`--max-usd`), and live calls are also written to the repo's usage ledger and refused by the existing Nous
budget stop. Inside Eshaan's roughly $10 a month.

## How to run it (on Eshaan's Mac, where the Nous key lives)

The key is read from `~/.hermes/.env` (`NOUS_API_KEY`) in-process and never printed. No key is needed for anything
else here.

```
git pull origin claude/project-thread-4gyfqw
uv run python scripts/fair_test.py smoke --live
uv run python scripts/fair_test.py run --live --max-usd 3
uv run python scripts/fair_test.py score
```

The smoke check costs well under a cent and ends with SMOKE CHECK PASSED or FAILED and the reason; start the full run
only after PASSED. Its replies are cached, so the full run reuses them. A stopped run resumes from the cache without
paying twice. Results land in `docs/research/fair-test-20261029/` (`rows_live.jsonl`, `cache_live.jsonl`,
`result_live.json`). `smoke --dry-run` and `run --dry-run` exercise everything with a fake model for $0.

The Nous budget stop reads the usage ledger of the checkout the run starts from (`ledger/v4.1-usage.jsonl`), so a
fresh worktree starts it at $0. The `--max-usd` cap holds either way.
